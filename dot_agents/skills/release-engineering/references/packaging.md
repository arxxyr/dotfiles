# 产物与部署

以下为新项目默认协议；已有安装器、分发格式和发布流程保持兼容。

## 版本与命名

权威来源保留 SemVer 的 `MAJOR.MINOR.PATCH`；附加信息在构建或打包阶段生成。

| 场景 | 产物完整版本 | 示例 |
|------|--------------|------|
| Release，推送 `v*` 标签 | `v{version}+{commit7位}` | `v0.3.0+abc1234` |
| Dev，分支推送 | `v{version}+{日期}.{commit7位}` | `v0.3.0+20260303.abc1234` |
| 本地部署 | `v{version}` | `v0.3.0` |

- 日期格式为 `YYYYMMDD`，一次构建中使用相同日期和提交；遵循项目既有时区约定。
- 提交标识取实际构建源码的前七位；不要把未包含的工作区改动标记为干净提交产物。
- 命名为 `{项目名}-{完整版本}-{平台}.{扩展名}`。

| 平台 | 默认扩展名 | 示例 |
|------|------------|------|
| Linux x64 | `.tar.gz` | `myapp-v0.3.0+abc1234-linux-x64.tar.gz` |
| Windows x64 | `.zip` | `myapp-v0.3.0+abc1234-windows-x64.zip` |
| macOS ARM64 | `.tar.gz` | `myapp-v0.3.0+abc1234-macos-arm64.tar.gz` |

## 包内容

```text
package/
├── 可执行文件或入口脚本
├── VERSION
└── 运行时必需资源/
```

- `VERSION` 为纯文本，内容必须与产物名中的完整版本一致。
- 默认不打包源码、测试和开发文档；包括必须的配置、字体、静态文件与运行时库。
- 遵守依赖分发许可；需要随包提供的 LICENSE/NOTICE 不因“仅运行时文件”被误删。
- 验证相对资源路径、执行位、动态库查找和解压后启动，不依赖开发机环境。

## 压缩

- Linux 编译型产物默认考虑 UPX `--best --lzma`，先确认二进制格式支持，并验证压缩后启动。
- Windows 跳过 UPX；无签名加壳程序容易触发安全软件启发式误报，不为体积牺牲可用性。
- Authenticode 签名按项目已有凭据与授权执行，不把签名当成绝不会误报的保证。
- macOS 跳过 UPX，保留目标平台签名与运行要求。

## 本地部署脚本

- 放入 `scripts/`：`deploy.sh`（Linux/macOS）和 `deploy-windows.ps1`（Windows）。
- 默认输出到项目 `bin/`；创建独立暂存目录后组装产物，避免打包无关历史文件。
- 跨平台初始化提供 `bootstrap.sh` 与 `bootstrap.ps1`；使用项目指定 Shell，避免 Bash 语法误放 POSIX 入口。
- Shell 检查环境时使用专用变量；PowerShell 根据 `$PSVersionTable` 和项目最低版本决定能力。
- 失败返回非零状态，传播构建和打包工具的退出码；删除旧产物前解析确切目标，不清空宽泛目录。
