# 项目工单集成

为 `planning`、`triage` 等工单流程补齐必要配置；本技能不安装其他技能。
已有配置足以完成任务时直接使用，不重新初始化。

## 读取已有约定

- 检查仓库现有指令、`docs/agents/` 和相关工单文档，读取远程地址以确认候选项目。
- 查看当前任务是否已明确系统、目标仓库、标签及发布授权；远程地址本身不表示发布授权。
- 已有领域文档时记录其实际路径；缺少 `CONTEXT.md` 或 ADR 不阻止配置和普通任务。
- 阅读目标文件前确认符号链接和管理方式，保留现有内容与用户改动。

## 补齐必要信息

- 只确认确实影响集成的缺失项，例如多个远程中哪个接收工单，或用户要求的自建平台地址。
- 明确配置直接复用；不要求按工单系统、标签、领域文档逐轮确认。
- 根据所选系统，只读取一份模板：[GitHub](issue-tracker-github.md)、[GitLab](issue-tracker-gitlab.md) 或 [本地 Markdown](issue-tracker-local.md)。
- 其他平台按其已有工具与项目约定记录；不把 GitHub 命令套到其他系统。
- 只有涉及分诊状态时读取 [标签映射](triage-labels.md)，读取现有标签后再映射，避免重复创建。
- 需要为 `design-review` 或 `planning` 提供已有领域文档位置时，读取 [领域文档参考](domain.md)。

## 最小配置改动

- 优先更新既有工单配置；确实缺失时可在项目惯用位置创建工单说明，例如 `docs/agents/issue-tracker.md`。
- 记录系统、明确目标、工具入口和实际工作约定；草稿与已发布工单需要能够区分。
- 已有 `AGENTS.md` / `CLAUDE.md` 引用区时原位更新；只补本次需要的引用，不覆盖其他章节。
- 两份指令同时存在时遵循其既有权威源与链接关系；不要为了初始化创建另一套指令文件。
- 项目无指令文件时，独立工单说明就足够，不要求新建 `AGENTS.md`、领域词汇表或 ADR 体系。
- 标签映射、领域路径只在实际需要时记录，不固定生成三份配置文件。
- 本地配置写入可在已授权集成范围内完成；远程标签、工单、评论等写入仍按具体任务授权执行。

## 验证与交付

- 检查链接、项目标识、选用工具是否一致；有可用访问能力时用只读查询验证目标。
- 不为验证配置创建测试工单或发送评论。
- 汇报实际改动与尚缺的访问条件，继续完成原来已授权的工单任务。
- 后续正常使用不重复运行本技能；切换系统或现有配置不足时再按需补齐。
