# chezmoi 配置维护

先确定源文件、目标文件和本次范围，再编辑。所有已纳管配置均修改 chezmoi 源，不直接改应用后的目标。

## 定位与检查

- 使用 `chezmoi source-path <目标文件>` 定位源；通过 `chezmoi source-path` 确认实际源仓库。
- 源仓库通常为 `~/.local/share/chezmoi`，以命令返回值为准，不把某台机器的绝对路径写入可移植配置。
- 检查源仓库状态、相关模板和目标漂移，保留用户已有修改，不将应用后的本机状态整批反向覆盖进源。
- 修改链接前用 `readlink` / `readlink -f` 核实目标、文件是否存在及实际权威源。
- 新配置先确定是否需要跨机器同步，再用 `chezmoi add <目标文件>` 纳管；纳管敏感配置前先完成加密或模板化。

## 修改、预览与应用

1. 编辑定位到的源文件；机器差异用模板与数据处理，不维护多份手工分叉。
2. 用 `chezmoi diff <目标文件>` 预览本次差异，核对渲染值、权限、链接和预期删除。
3. 用 `chezmoi apply <目标文件>` 只应用本次目标；涉及脚本或钩子时先检查其实际影响范围。
4. 验证工具能加载配置、链接有效，再次定向检查 diff，确认没有意外漂移。
5. 按用户提交约定只暂存相关源文件并提交；推送、远程发布等按已有任务授权执行。

预览若出现本次范围外漂移，先查来源并保留它；不通过整库 apply 顺带覆盖。

## Agent 指令与技能

- 应用后的指令权威文件为 `~/.claude/CLAUDE.md`；`~/.codex/AGENTS.md`、`~/.agents/AGENTS.md` 指向它。
- 个人技能权威目录为 `~/.agents/skills/`；Claude、Codex、OpenClaw 的个人技能入口按源仓库定义链接到对应技能。
- 上述应用路径仍是生成目标；编辑前继续通过 `chezmoi source-path` 回到受版本管理的源。
- 同名技能需要区分个人、系统与插件来源；系统和插件技能由所属组件维护，不复制进个人源形成重复维护。
- 维护技能时同步核对源码、链接、安装记录和恢复入口；锁记录本身不能恢复缺失文件。
- 删除入口前核对实际目标，保留可恢复的源仓库记录；不根据失效链接推断可以删除其他目录。
- 安装恢复只能覆盖明确保留的技能，移除的个人技能不应被旧锁记录或安装脚本重新装回。
- 排查客户端未加载指令、重复加载或旧机器历史时，读取 [客户端发现与历史记录](references/client-discovery.md)，按当前版本复验。
- 维护 macOS Draw.io 导出命令或样式约定时，读取 [工具备忘](references/tool-notes.md)。

## 密钥与权限

- 含真实密钥或令牌的配置采用 `encrypted_` 文件（age/gpg），或用模板从密码管理器读取。
- `private_` 只控制目标权限，不加密内容；不能用它保护公开仓库中的明文秘密。
- 预览、日志和提交差异避免显示实际秘密；密钥值不进入命令行、示例或临时明文副本。
- 发现已提交秘密时停止继续传播并说明实际问题，撤销与历史清理由相应授权决定。

## 交付检查

- 报告源文件的实际变更、应用与加载验证结果，以及提交和推送的真实状态。
- 删除了哪些入口、保留了什么权威内容、如何从版本记录恢复，按实际结果简要说明。
- 跨机器恢复验证覆盖所需模板数据与链接目标；未验证的平台明确标记，不把本机成功视作全平台成功。
